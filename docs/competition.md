## 创赛任务总控

入口：[`crv-contest-router`](../skills/crv-contest-router/SKILL.md)。

梳理创业竞赛项目材料，识别BP、PPT、答辩交付，选择一个主要工作流。

**准备资料**：比赛与阶段；已有资料；目标交付物及评分要求。

**预期产出**：事实与证据清单；最小工作流选择；修改顺序。

**执行重点**：

- 先分清创业计划、学术作品申报以及演示任务；规则未知时只问影响交付的关键事项。
- 将项目事实分成已完成、测试中、意向与计划，并记录证据位置和日期。
- BP选择crv-challenge-bp或crv-business-plan；演示选择crv-contest-deck；只有出现相应缺口才追加其他视角。
- 交付时统一各材料中的项目名称、指标、时间、团队贡献和预测假设。

**边界与依赖**：能够读取用户材料的Agent；实际文件编辑由当前环境工具完成。

- 总控负责选择与统稿，不默认逐一运行所有技能。
- 不把意向、预测或概念验证改写成已成交、已实现或量产。

```text
$crv-contest-router 基于项目资料，判断当前小挑BP和路演稿的主要缺口，先统一事实，再完成最重要的章节。
```

## 小挑创业计划书

入口：[`crv-challenge-bp`](../skills/crv-challenge-bp/SKILL.md)。

撰写或审查挑战杯创业计划类BP，对齐实际模板、项目阶段和评分证据。

**准备资料**：赛事通知与模板；是否注册与实际项目阶段；用户、技术、验证、团队材料。

**预期产出**：章节正文；证据对应表；待补信息。

**执行重点**：

- 以用户提供的赛事模板为目录依据，确认申报主体和项目成熟度。
- 沿需求、方案、验证、客户价值、商业路径组织论证，每项关键主张对应证据。
- 财务部分区分历史事实和预测，说明数量、单价、成本与时间范围等假设。
- 审查跨章节数字和能力表述，最后按篇幅要求收敛正文。

**边界与依赖**：文本与表格读取工具；需要Word时使用可用的文档编辑工具。

- 学术作品申报应按该作品的实际要求处理。
- 不提供固定官方评分权重或保证获奖的表述。

```text
$crv-challenge-bp 根据比赛模板和现有证据重写商业模式章节，列出每个结论的依据和预测假设。
```

## 商业计划分章写作

入口：[`crv-business-plan`](../skills/crv-business-plan/SKILL.md)。

根据项目事实与公开证据撰写市场、产品、商业模式、财务和实施章节。

**准备资料**：项目主档；用户与市场资料；章节要求和财务假设。

**预期产出**：章节分析；正式正文；来源与假设清单。

**执行重点**：

- 先建立事实主档，明确客户、产品、阶段、成果和术语。
- 公开检索只补行业与竞品事实，将信息来源和时点写入证据清单。
- 分别分析客户决策、产品价值、触达渠道、收入与成本，检查它们是否相互支持。
- 先形成判断与证据的提纲，再写连续正文并统一本章与其他章节的口径。

**边界与依赖**：有来源记录的资料检索；表格与文件输出工具按实际任务选择。

- 公开资料不能用于补造私有订单、合作或团队经历。
- 按实际项目需要确定篇幅与图表数量。

```text
$crv-business-plan 围绕给出的客户、成本和渠道资料完成市场与财务章节，区分事实、估算和后续计划。
```

## 创赛PPT内容设计

入口：[`crv-contest-deck`](../skills/crv-contest-deck/SKILL.md)。

把创业项目转成网评、路演或答辩PPT的页序、结论和证据安排。

**准备资料**：BP与证据；展示场景和受众；页数、时长与评分要求。

**预期产出**：逐页内容稿；讲稿安排；证据与页面对应。

**执行重点**：

- 区分自行阅读的网评稿和配合讲解的路演稿，依据时长调整信息密度。
- 为每页写出一个待证明的结论，并指定支持它的资料或图表。
- 安排问题、解决方案、验证、实施与团队等内容的承接，删除没有作用的重复页。
- 用户需要实际PPTX时选择原生或图片路线，完成后检查渲染和数据一致性。

**边界与依赖**：需要PPTX时必须具备实际演示制作与渲染工具。

- 逐页文案不是已经生成的演示文件。
- 匿名和附件要求按本次赛事通知处理。

```text
$crv-contest-deck 将这份BP规划成6分钟路演，输出逐页结论、证据位置和对应口头讲稿。
```

## 商业逻辑审查

入口：[`crv-business-review`](../skills/crv-business-review/SKILL.md)。

审查需求、技术价值、竞争差异和价值获取之间的断点，给出可执行修改。

**准备资料**：具体项目或章节；目标客户与替代方案；已有验证和商业路径。

**预期产出**：逻辑问题；验证问题；修改建议。

**执行重点**：

- 将客户、问题、替代方案、价值和收入机制写成明确陈述。
- 逐项检查因果链，区分“存在问题”和“客户愿意为解决方案投入资源”。
- 按影响程度列出断点，每个断点给出需要的证据、修改方向或验证行动。

**边界与依赖**：文本分析；现实市场判断需要可核查资料。

- 采用客观分析，不扮演现实人物或声称得到其认可。
- 缺少事实时明确分析条件，不用强烈措辞代替证据。

```text
$crv-business-review 审查这一章从技术优势到客户付费的逻辑，逐条给出问题、证据要求与改法。
```

## PPT单页逻辑

入口：[`crv-slide-logic`](../skills/crv-slide-logic/SKILL.md)。

优化已有幻灯片的结论标题、信息主次和证据表达。

**准备资料**：页面文字或截图；页面要证明的观点；受众与真实数据。

**预期产出**：结论标题；删改清单；信息层级建议。

**执行重点**：

- 先说明该页应让读者记住的一条结论。
- 检查图、数据、正文是否共同支持它；将旁支移到其他页或备份页。
- 改写标题并调整阅读顺序，保留关键条件、单位和来源。

**边界与依赖**：图片或PPT读取能力；实际修改文件需要对应编辑工具。

- 不为了标题冲击力扩大样本、测试或预测的适用范围。
- 这是通用审稿视角，不代表任何现实讲师意见。

```text
$crv-slide-logic 检查这三页是否一页一事，分别给出结论标题、保留内容和需要移动的证据。
```
